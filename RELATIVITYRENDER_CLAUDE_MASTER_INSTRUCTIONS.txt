# RELATIVITYRENDER — CLAUDE CODE MASTER INSTRUCTIONS

Read this file at the beginning of EVERY Claude Code session/prompt before making changes.

You are building RelativityRender, a serious GPU renderer platform.

RelativityRender is NOT:
- a toy renderer
- a small demo
- just a Cinema 4D plugin
- an Octane clone

RelativityRender IS:
- a serious GPU renderer platform
- CUDA/OptiX-first
- designed around GPU path tracing and ray-level relativistic perception
- eventually integrated with Cinema 4D
- unique because of its relativistic camera/perception model

Long-term goal:
Build a production-style GPU renderer platform with:

- CUDA backend
- OptiX backend
- path tracing
- shader/material system
- material node graph
- texture system
- lighting system
- scene graph
- progressive rendering
- denoising
- AOVs/render passes
- renderer server
- Cinema 4D bridge
- future native Cinema 4D renderer integration
- unique relativistic camera/perception model:
  - relativistic aberration
  - Doppler color shift
  - searchlight/headlight effect
  - Lorentz-style perception
  - retarded-time approximation

CORE ENGINEERING RULES

1. Build incrementally.
2. Keep every step compilable.
3. Do not implement fake stubs pretending to be complete systems.
4. Do not jump to UI, Cinema 4D bridge, native C4D renderer, or node editor too early.
5. No CPU ray tracing as production path.
6. CPU may only:
   - orchestrate execution
   - parse/load scenes
   - manage IO
   - upload data to GPU
   - launch CUDA/OptiX kernels
   - receive framebuffers
   - save image files
   - run server/IPC
7. All per-pixel/per-ray rendering must happen on GPU.
8. Update docs/BUILD_PLAN.md after every implementation.
9. Keep module boundaries clean.
10. Avoid monolithic files.
11. Prefer explicit, testable interfaces.
12. Do not overbuild a later system before the current layer works.

DEPENDENCY RULES

Core modules must never depend on:
- Cinema 4D
- UI
- node editor
- external DCC applications

Renderer backend must not depend on:
- Cinema 4D bridge
- UI code
- editor tools

Cinema 4D bridge must depend on exported scene format/server protocol, not internal renderer implementation.
